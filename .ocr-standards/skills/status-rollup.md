# Skill: /status-rollup — Fleet "Where Are We?" Auto-Snapshot

Per `OCR-docs/docs/skills/OCR_SKILL_statusRollup.md` (the design spec) and
`OCR-docs/OPERATING_SYSTEM.md §3` routing matrix — this skill regenerates
the single fleet snapshot at `OCR-docs/STATUS.md` so it stops drifting.

## When to Use

User says: "/status-rollup", "status rollup", "where are we", "Friday
status", "fleet status", "weekly rollup", "status check", or invokes
this skill directly from a scheduled job.

Cadence (per `OPERATING_SYSTEM.md §5`):

- **Friday 09:00** automated (scheduled task)
- **Manual** any time
- **Per-launch milestone** immediately after a Phase-N ship

## Token Budget

Under 60 tool calls. **EARLY BAIL** if no PRs merged + no Linear story
state changes since last `STATUS.md` write — write a one-line "no
changes since YYYY-MM-DD" note to STATUS.md and stop. Target <15 calls
on quiet days.

## Prerequisites — read first

1. `OCR-docs/OPERATING_SYSTEM.md` — fleet routing + cadence rules
2. `OCR-docs/CURRENT_STATE_INVENTORY.md` — open gaps (G1–G11+) and
   their owners
3. `OCR-docs/STATUS.md` (if exists) — previous run's headline + date,
   for the diff window

## Inputs to gather

| # | Source                            | How                                                                                                                                                            |
| - | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | **Linear** — story state changes  | `list_issues` MCP tool, workspace "OurSharedEvents", limit 250. Compare against last run's snapshot.                                                            |
| 2 | **Git log** across 9 surfaces     | One `git log --since='7 days ago' --oneline` per repo. Repos: 7 product + workspace root + OCR-docs. PRs merged this week.                                      |
| 3 | **ADR directories**               | New / status-changed files in `<repo>/docs/adr/` (each repo) + `OCR-docs/docs/adr/`.                                                                            |
| 4 | **Brain contract diffs**          | `git log --since='7 days ago' --oneline -- ocr-docs-brain/` from inside `OCR-docs`.                                                                             |
| 5 | **SharedReport signal** (OSE)     | `POST /api/v2/events/shared-reports/batch` with this week's active venue event IDs. Endpoint lives at `https://oursharedevents.com` (prod) or staging URL.     |
| 6 | **Gaps**                          | Parse `OCR-docs/CURRENT_STATE_INVENTORY.md §6` for current G1–GN gaps + their closing PR / owner.                                                               |

**Auth handling per source:**

- Linear: MCP-tool-mediated (no manual token).
- Git: local clones (preferred for speed) or `gh api` fallback.
- SharedReport: needs `WKRP_SERVICE_TOKEN` (Doppler:
  `ourcommunityrituals/dev_personal`). If unset → skip §"SharedReport
  signal" with a structured note in `_meta.suppressed_sections`.
- Brain diffs: `git log` only; no auth needed.

## Failure isolation

Any single source failure (Linear API down, one repo unreachable,
SharedReport endpoint not yet deployed) **degrades the output
gracefully**:

- The skill writes the sections it CAN compute.
- Missing sections render as `_Section unavailable — <reason>_`.
- A `## Status: degraded` block at the top names what was missing.
- The skill does NOT abort.

## Steps to execute

1. **Read prior STATUS.md** (if exists). Note its `generated_at`. This
   is your diff window. If file does not exist → first run → window is
   "all available history past 7 days."

2. **Early-bail probe** (≤ 3 tool calls):
   - `gh api repos/ourCommunityRituals/ourSharedEvents/pulls?state=closed&per_page=10 --jq '.[].merged_at'`
     to see if any PR merged since last run. If no merges and Linear
     story state is unchanged (call `list_issues` once, hash and compare)
     → write `"No changes since <prior date>"` to STATUS.md and stop.

3. **Gather Linear**: `list_issues` (one call), parse for stories
   that moved status this week (compare to prior STATUS.md
   per-product table).

4. **Gather git log** for the 9 surfaces. Local `git log --since='7
   days ago' --oneline` per repo. **Do not switch branches** — work
   from each repo's current HEAD.

5. **Gather ADRs**: glob `*/docs/adr/ADR-*.md` + `OCR-docs/docs/adr/ADR-*.md`,
   read each file's `**Status:**` line, compare to prior STATUS.md.

6. **Gather Brain diffs**: `git log --since='7 days ago' --oneline -- ocr-docs-brain/`
   from inside `OCR-docs`.

7. **Gather SharedReport signal** (if endpoint live): POST to the
   batch endpoint with this week's active OSE event IDs.

8. **Gather inventory gaps**: read `OCR-docs/CURRENT_STATE_INVENTORY.md §6`,
   parse `G1…GN` block, for each gap check the inventory's "closes
   when" status against current state.

9. **Synthesize TL;DR**: 3 bullets that a busy founder reads in 20
   seconds. Pick the highest-leverage win + biggest blocker + named
   next-milestone-with-date.

10. **Write STATUS.md**. Use the template above. Stage but DO NOT
    commit — operator runs `git add OCR-docs/STATUS.md && git commit`
    explicitly (per `feedback_no_auto_prod_deploy.md` — auto-commits
    are forbidden).

11. **Report back** to the invoking user: "STATUS.md regenerated.
    `<N>` tool calls. `<list_of_sources_used>`. Run `git diff
    OCR-docs/STATUS.md` to review; commit when ready."

## Anti-patterns

- ❌ Don't include raw query results in `STATUS.md`. Aggregate.
- ❌ Don't auto-commit the output. Stage only.
- ❌ Don't grow past 200 lines. If a section would exceed its slot,
  truncate with `…` and link to the source file.
- ❌ Don't run during a fresh week with no signal — early-bail.
- ❌ Don't embed `anon_id_hash` or any per-attendee data. Only
  aggregates flow through this skill (it calls the SharedReport
  read API which already enforces this).
